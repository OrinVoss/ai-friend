## T1（#244）：前端 Cookie SameSite

### 现状核实（已确认，执行时复核即可）

- 名称硬编码：已修（`app.js` 用 init_ok 的 `data.name`，默认值 `'AI'`）——**不用动**。
- 重连风暴：已修（指数退避 2s→30s）——**不用动**。
- Cookie 安全标志：`web/static/app.js:81-83`：

```javascript
function setCookie(name, value) {
    document.cookie = name + '=' + value + '; path=/; max-age=86400';
}
```

### 修法

`setCookie` 与 `clearCookie`（:85-87）的 cookie 串都追加 `; SameSite=Lax`。

**不要加 `HttpOnly` 或 `Secure`**：session_id 由 JS 写入、JS 读取后放进 WS init 消息，HttpOnly 会让 JS 读不到、会话直接失效；localhost 是 http，Secure 会导致 cookie 写不进去。在代码注释里写明这两个决策（防止后人再踩）。

### 测试与验收

- 仿照 `tests/test_web_startup.py` 的源码断言风格，加一个测试：读 `web/static/app.js` 源码，断言 setCookie/clearCookie 两处都含 `SameSite=Lax`。

## T2（#263）：async_utils 超时取消传播

### 根因

`core/async_utils.py` 有循环分支（:33-43）：

```python
ctx = contextvars.copy_context()
future = _EXECUTOR.submit(ctx.run, asyncio.run, coro)
try:
    return future.result(timeout=timeout)
except concurrent.futures.TimeoutError:
    future.cancel()   # 对已运行的线程是 no-op：协程在后台继续跑（僵尸）
    raise
```

超时的协程（可能正在写 DB）继续执行——AU-002/AU-003 未根治。无循环分支（:28）已在 #263 前半修过（`asyncio.wait_for`），不用动。

### 修法

让 worker 内的协程句柄可外部取消，超时时把 `cancel()` 经 `call_soon_threadsafe` 送进 worker 的事件循环。把 :33-43 替换为：

```python
    # Already inside an event loop — use a thread to run the coroutine.
    ctx = contextvars.copy_context()
    holder: dict = {}  # worker 启动后填入 task 句柄，供超时取消

    async def _body():
        task = asyncio.ensure_future(coro)
        holder["task"] = task
        return await task

    future = _EXECUTOR.submit(ctx.run, asyncio.run, _body())
    try:
        return future.result(timeout=timeout)
    except concurrent.futures.TimeoutError:
        # #263 AU-002/AU-003: 取消传播进协程——CancelledError 会进入协程的
        # try/finally（DB rollback 等清理得以执行），不再留僵尸线程。
        task = holder.get("task")
        if task is not None and not task.done():
            task.get_loop().call_soon_threadsafe(task.cancel)
            try:
                future.result(timeout=5)  # 给清理代码短暂收尾窗口
            except Exception:
                pass  # CancelledError/超时都属预期，结果已被放弃
        else:
            future.cancel()  # worker 尚未排上队，直接取消
        logger.error(f"[async] coroutine timed out after {timeout}s, cancelled")
        raise
```

注意点：
- 保留现有的 `ctx = contextvars.copy_context()`（A3 的 request_id 传播，别弄丢）。
- `asyncio.run(_body())` 在 worker 线程里跑，`_body()` 里 `ensure_future` 创建的 task 属于该线程的 loop；`task.get_loop().call_soon_threadsafe` 是跨线程取消的标准做法。
- docstring 里"超时只是放弃等待"的旧注释同步更新。

### 测试

- `tests/test_async_utils.py`（已存在）新增：
  1. 在已有事件循环的线程里调 `run_async`（用 `asyncio.run` 包一层制造 running loop），coro 内部 `try/finally` 记录清理标记并 `await asyncio.sleep(60)`，timeout 设 0.1~0.5s；断言抛出 TimeoutError **且 finally 清理标记被置位**（取消真的进了协程）。给清理一个短等待（如 0.5s）再断言。
  2. 正常完成的协程结果不受影响（现有用例不降级）。
- 全量测试不降级。

## T3（#164）：记忆固化 LLM 调用合并

### 根因

`memory/consolidation.py::consolidate()`（:90-166）每批固化最多 3 次独立 LLM 调用：

1. Step 1 `_extract_facts(turn_text)`（:127）→ `FACT_EXTRACTION_PROMPT`
2. Step 2 `_summarize_experience(turn_text)`（:135，仅 len>200）→ `EXPERIENCE_SUMMARIZATION_PROMPT`
3. Step 3 `_generate_reflection_l1/l2/l3`（:146-150）→ `REFLECTION_PROMPT` / L2 / L3

目标：把 Step 1+2+3(L1) 合并为**一次**调用，L2/L3 节奏（每 3/10 次）保持独立调用不变。效果：常规批次 3→1 次，L2/L3 批次 3→2 次。

### 修法

**第 1 步：抽出解析逻辑（让两条路径共用）**

把现有三个方法拆成"调用 LLM 取文本"与"解析文本落库"两半：

- `_extract_facts` → 抽 `_parse_fact_lines(text, observation_ids)`（现有 FACT| 行解析 + FactChecker + bulk 写库逻辑原样搬入，保持"先检测后落库"顺序）
- `_summarize_experience` → 抽 `_parse_experience_block(text, short_term)`
- `_generate_reflection_l1` → 抽 `_parse_insight_block(text, personality)`（注意 L1 二期已改结构化 Insight 输出，落 insights_v2——按当前代码为准，不是旧的开放式 Reflection）

旧方法保留为"调用 LLM + 调解析函数"的薄壳，**旧路径行为一字不差**（灰度回退用）。

**第 2 步：统一 prompt 与合并路径**

`prompts/templates.py` 新增 `CONSOLIDATION_UNIFIED_PROMPT`，输入变量合并三者所需（`{text}`、`{experiences}`、`{reflections}`、`{facts}`、`{current_emotion}`、`{relationship}`——先读 L1 生成方法的现状，确认 L1 实际用了哪些变量），输出格式硬性分段：

```
FACTS:
FACT|category|key|value|confidence|importance|fact_type
（每行一条，没有则写 NONE）

EXPERIENCE:
SUMMARY: ...
TONE: ...
SIGNIFICANCE: 0.x
IMPORTANCE: 0.x
TAGS: a,b,c

INSIGHT:
TYPE: ...
CONTENT: ...
SIGNIFICANCE: 0.x
```

`MemoryConsolidator` 新增 `_consolidate_unified(turn_text, short_term, personality, lifecycle_obs_ids)`：一次 `provider.generate` → 按 `FACTS:` / `EXPERIENCE:` / `INSIGHT:` 分段 → 分别喂给三个解析函数。分段缺失/解析失败只跳过该段（error isolation 与现状一致，记 warning 并记进 `errors`）。

**第 3 步：接线 + 灰度开关**

- `config.py` / `config.example.json`：新增 `consolidation_unified_call: bool = True`。
- `consolidate()` 中 Step 1~3 替换为：

```python

l1_turn = (self._consolidation_count + 1) % 3 != 0 and (self._consolidation_count + 1) % 10 != 0

    self._consolidation_count += 1

    # 旧三次调用路径原样保留（含 L2/L3 节奏判断）
```

- L2/L3 节奏批次走旧路径（保持 L2/L3 语义与现有测试不变）。
- `doc/config-reference.md` 同步新配置项。

**第 4 步：解析容错**

统一输出不符合三段格式时，记 warning 并整体回退到旧三次调用路径（不丢本批数据）。回退只在本批生效，不写状态。
