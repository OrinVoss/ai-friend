# 2026-07-13 修复嵌入 API 400 + 主动消息不持久化

## 问题一：嵌入 API 400

### 现象
`memory/embeddings.py` 持续报 400 错误：
`[embed] API failed: 400 Client Error: Bad Request for url: http://localhost:8080/v1/embeddings`

### 根因
llama.cpp 的 `/v1/embeddings` 接口不接受空字符串。当 `{"input": [""]}` 或
`{"input": ["", "正常文本"]}` 时返回 400（正常文本返回 200，超长文本返回 500）。
应用中存在传入空字符串的场景（如检索 query 为空时），导致 API 级联失败。

### 修复
`_encode_locked()` 中，发往嵌入 API 前过滤掉空文本：
- 非空文本正常请求 API，结果按索引匹配
- 空文本直接赋零向量（长度 = embedding_dim），不请求 API
- 全部为空时跳过 API 请求

## 问题二：主动消息不持久化

### 现象
AI 的主动消息（主动打招呼/分享探索结果）刷新页面后消失，用户看不到历史记录。

### 根因
`handle_proactive()` 和 `handle_explore()` 调用 `_react_loop` 时传了
`add_to_history=False`，导致主动回复不写入短期记忆（short_term）和数据库
（conversation_turns）。

### 修复
`core/message_handler.py`：两个主动方法的 `_react_loop` 调用均改为
`add_to_history=True`（与睡眠/唤醒消息保持一致，后者已在 lines 374-375
独立持久化）。
同时更新 CLAUDE.md 中的过时规则。

## 修改文件
- `memory/embeddings.py` — 过滤空字符串后再请求嵌入 API
- `core/message_handler.py` — 主动消息改为持久化
- `CLAUDE.md` — 更新过时规则
- `changes/` — 本记录
