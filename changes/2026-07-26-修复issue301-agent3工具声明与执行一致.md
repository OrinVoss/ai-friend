# 2026-07-26 Fix #301: Agent 3 工具声明与执行 registry 一致

## 修改原因

Issue #301：Agent 3（Roleplay）prompt 的「可用工具」块渲染全量 10 个工具（含 7 个外部工具），
并指示模型直接 `<tool_call>` 调用；但 ReAct 执行侧 registry 仅含内部工具
（recall/remember/history_search），直接调用外部工具会得到「未知工具」（not_found）。
H-01（d1596da）只收窄了执行侧，prompt 侧未同步，注释声称的一致性并不成立。

## 修改的文件

- `prompts/system.py`：`build_system_prompt` 新增 `rule_tools=None` 参数（缺省回退 `tools`，
  向后兼容）；「可用工具」块用 `tools`（执行 registry），输出规则块的 intent 选项用
  `rule_tools`（全量 registry）——与 Agent 1 侧 M-06 同款模式。
- `core/message_handler.py`：三个调用点（`_run_agent3`、`handle_proactive`、`handle_explore`）
  统一改为 `tools=self._make_internal_registry(include_history_search=True)` +
  `rule_tools=a.tool_registry`；H-01 注释更新。
- `tests/test_prompt_instructions.py`：新增 `TestAgent3RuleTools` 护栏测试——断言工具块
  仅含内部工具、intent 选项（play_music/search_web/fetch_url）仍从全量 registry 派生、
  `rule_tools=None` 时回退兼容。
- `doc/message-flow.md`：意图回路一节补四字段 JSON 结构与 #301 一致性说明。
- `doc/prompt-reference.md`：Block 7 / Block 12 数据来源更正。

## 设计要点

- 不能简单从 prompt 拿掉全量 registry：输出规则块的 `format_intent_options` 需要它派生
  intent 选项，这是 Agent 3 → JSON intent（reply_to_user/intent/intent_description/
  intent_target 四字段）→ Agent 1 `assess_agent3_intent` 审批 → Agent 2 执行 的正规通道。
- 修复后：内部工具直接 `<tool_call>`，外部动作只能走 intent 回路，声明与执行一致。
