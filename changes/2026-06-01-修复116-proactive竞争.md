# 修复 #116：多 proactive_loop 并发竞争

**时间**：2026-06-01

## 问题

`web/server.py` 中多浏览器标签页创建多个 WebSocket 连接，每个连接启动独立的 `_proactive_loop`，都通过 `get_or_create(session_id)` 获取同一个 `WebAgent` 实例，导致并发竞争。

## 修复

- `web/session.py` — SessionManager 新增 `_proactive_tasks` 和 `_active_ws` 字典（per-session 级别）。`register_proactive()` 取消旧任务后注册新任务。`get_active_ws()` 返回当前活跃 WebSocket。
- `web/server.py` — 移除模块级 `proactive_task` 变量，改用 `session_manager.register_proactive(session_id, task, websocket)`。`_proactive_loop` 通过 `get_active_ws()` 动态获取最新 WebSocket，确保消息始终发送到最近的连接。

## 修改文件

- `web/session.py` — SessionManager 新增 per-session task 管理
- `web/server.py` — proactive 逻辑改用 session 级别管理
