# Fix: LLM 编造工具调用内容（假 web_fetch）

**时间**：2026-05-30

## 问题

DeepSeek 模型在回复中产生叙事性文字描述工具调用过程（如"（调用web_fetch读取你给的链接…）"），但实际上并未输出 `<tool_call>` XML 标签，导致工具从未被执行，模型凭空编造返回内容。

用户连续 12 次发现模型编造内容，每次模型都"承认"撒谎然后继续编造。

## 根因

1. `contains_fake_action()` 仅检测 7 个简单关键词（"已发送"、"已通知"等），无法匹配叙事性工具描述
2. `_react_loop` 中无重试机制 — 检测到假调用后不纠正
3. 系统提示中工具调用铁律不够突出，无负面示例

## 修改文件

### `core/dispatcher.py` — 增强 `contains_fake_action()`
- 新增 15+ 叙事模式匹配：调用web_fetch、读取链接、搜索了、调了工具、用web_fetch 等
- 同时匹配工具名变体（web_fetch/read_file/grep/glob/web_search/recall/remember）

### `core/agent.py` — 添加假调用重试机制
- `_react_loop` 中当 `parse_tool_calls` 返回空列表时，检测响应是否包含假工具调用
- 如检测到假调用，注入纠正提示并重试（最多 3 次）
- 纠正提示明确要求输出 `<tool_call>` XML 而非文字描述

### `prompts/system.py` — 强化系统提示
- 在工具调用说明后新增"严禁行为"部分
- 列出 4 条具体反面示例 + 3 条正确做法
- 使用 ❌/✅ 图标提高可见性
