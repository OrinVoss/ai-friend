# run_async 重入防护

## 修改文件

- `core/async_utils.py`
- `tests/test_async_utils.py`

## 修改原因

`core/async_utils.py` 的 `run_async` 在已有事件循环时使用 4 线程 `ThreadPoolExecutor` 桥接。若某个在 worker 线程新事件循环里运行的协程，又调用了一个内部走 `run_async` 的同步函数，会再次向同一个线程池提交任务并阻塞当前 worker；4 个 worker 同时处于此状态即互相等待，表现为 60 秒级卡顿。需把潜在嵌套调用从"卡顿"变成"立刻报错可定位"。

## 修改内容摘要

1. `core/async_utils.py`：
   - 引入 thread-local 变量 `_run_async_local` 作为重入标记。
   - `run_async` worker 分支入口检查标记：若已处于 worker 执行中，记录 error 日志并抛出 `RuntimeError("nested run_async call")`。
   - 将原 `ctx.run(asyncio.run, _body())` 包装为 `_worker()` 函数，在 worker 线程内设置/清除重入标记。

2. `tests/test_async_utils.py`：
   - 新增 `test_nested_run_async_rejected`：在外层线程创建事件循环并调用 `run_async`，使协程在 worker 线程执行；协程内部同步回调再次调用 `run_async` 时，断言抛出 `RuntimeError("nested run_async call")`。

## 验证

- `python -m pytest tests/test_async_utils.py -q` → 5 passed。
