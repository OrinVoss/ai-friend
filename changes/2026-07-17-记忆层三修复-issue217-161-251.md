# 记忆层三修复（#217 / #161 / #251）

日期：2026-07-17

## 修改的文件

- `storage/repository.py`
  - `upsert_fact`：`ON CONFLICT DO UPDATE` 两个分支（含/不含 embedding）新增
    `is_active = 1, composite_score = excluded.composite_score`（#217：复活被
    FactChecker 矛盾软删的同名事实；excluded 取 INSERT 默认值 1.0）。
  - 新增 `store_facts_bulk(facts)`：单 cursor 单事务批量 upsert，末尾一次 commit，
    SQL 与 `upsert_fact` 非 embedding 分支一致（#161，含 #217 复活语义）。
  - `prune_reflections`：加注释记录已知限制——is_active=0 的反思无任何读取路径（不改行为）。
  - `_row_to_reflection`：读出 embedding / embedding_version（#251）。
- `models/memory.py`：`Reflection` 新增 `embedding` / `embedding_version` 字段（#251）。
- `memory/long_term.py`：新增 `_store_facts_bulk` 及同步包装 `store_facts_bulk`（#161）。
- `memory/consolidation.py` `_extract_facts`：逐条解析 + FactChecker 逐条顺序检测
  （语义不变）→ 收集通过的 facts → 末尾 `store_facts_bulk` 一次落库；N 次
  upsert+commit 降为 1 次（#161）。
- `memory/retrieval.py`
  - 新增 `search_reflections(query, limit=3)`：候选池最近 30 条，有 embedding 走
    混合评分（语义 0.6 + 关键词 0.4，同 `_hybrid_score`），无则关键词评分；
    query 为空回退按时间取最近（#251）。
  - `retrieve_for_query` / `retrieve_by_recall_tag` 有 query 时改用 `search_reflections`。
  - `_extract_keywords` 公共化为 `extract_keywords`（保留私有别名兼容）。
- `tools/memory_tools.py`：RecallTool 改调公共 `extract_keywords`。
- 测试：`tests/test_repository.py`（#217 复活×2、#161 批量等价/复活/单 commit/空列表）、
  `tests/test_retrieval.py`（#251 语义排序/关键词排序/空 query 回退）、
  `tests/test_consolidation.py`（三处断言适配批量接口）。

## 原因

- #217：软删事实（is_active=0, composite_score=0）即使用户重述、upsert 命中冲突
  更新也永久不可见（所有查询过滤 is_active=1）。
- #161：`_extract_facts` 每条新事实独立 upsert+commit，N+1 写入。
- #251：反思检索只按时间取最近 N 条，与 query 无关；reflections 表已有 embedding。

## 验证

- `python -m pytest tests --ignore=tests/real_api -q` → 557 passed, 2 skipped（全绿）。
