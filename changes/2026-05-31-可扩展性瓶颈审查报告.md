# 可扩展性瓶颈审查报告

**日期**: 2026-05-31
**修改文件**: `doc/round05-scalability-bottlenecks.md`（新建）
**关联文档**: `doc/round05-memory-usage.md`, `doc/round05-database-performance.md`, `doc/round05-api-efficiency.md`, `doc/round05-caching.md`

## 修改原因

对 AI Friend 项目进行第5轮性能与可扩展性审查，聚焦扩展瓶颈。审查覆盖9个核心维度：单实例架构限制、SQLite并发瓶颈、单Provider连接限制、内存会话上限、上下文长度硬限制、多用户扩展能力、多模型切换支持、水平扩展可行性、长期数据增长影响。

## 修改内容摘要

- 新建审查报告 `doc/round05-scalability-bottlenecks.md`，约 9000 字
- 识别出 28 项具体扩展瓶颈，按 Critical/High/Medium/Low 分级
- 提供扩展能力矩阵（当前上限 vs 优化后上限）
- 给出架构演进路线图（阶段0→阶段3）
- 按 P0/P1/P2/P3 优先级给出修复建议

## 关键发现

| 维度 | 最严重问题 | 风险等级 |
|-----|-----------|---------|
| 单实例架构 | 全局唯一 SessionManager，无法多进程部署 | Critical |
| SQLite 并发 | 单连接+全局Lock串行化，QPS < 10 | Critical |
| Provider 连接 | 同步 requests 阻塞事件循环，并发 < 16 | Critical |
| 会话上限 | cleanup_old 硬编码50，无TTL机制 | Critical |
| 多用户扩展 | 无 user_id 隔离，数据全局共享 | Critical |
| 水平扩展 | 状态全部在进程内存，无法水平扩展 | Critical |
| 上下文长度 | _MODEL_CONTEXT 180K 超出模型能力 | Medium |
| 多模型支持 | Provider 硬编码，无抽象接口 | High |
| 长期数据增长 | 无归档策略，数据库无限膨胀 | High |
