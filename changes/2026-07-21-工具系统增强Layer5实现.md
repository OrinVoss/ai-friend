# 工具系统增强（Layer 5）实现

依据 `doc/refactor/layer5-tool/enhancement-plan.md` 执行计划，完成工具系统从「能用」到「好用」的升级。

## 改动文件

- `tools/traits.py`
  - `ToolResult` v2：新增 `error_type`、`retryable`、`elapsed_ms`。
  - 新增错误类型常量与中文 guidance。
  - `Tool` 基类新增 `timeout_seconds`、`is_internal` 元数据。

- `core/dispatcher.py`
  - 执行前按 `parameters_schema()` 校验必填参数与类型。
  - 调用 `check_permission()` 强制执行权限，拒绝返回 `permission_denied`。
  - 使用 `ThreadPoolExecutor` 并行执行独立工具调用，延迟从求和变取最大。
  - 每个工具按 `timeout_seconds` 单独超时，超时返回 `network_error(retryable=True)`。
  - 结果统一返回结构化字段：`error_type`、`retryable`、`elapsed_ms`。
  - `format_tool_results` 在失败时附加错误类型与是否可重试提示。

- `core/tool_agent.py`
  - `ToolCallRecord` 扩展 `error_type`、`retryable`。
  - `run_with_request` 按错误类型决定是否重试：
    - `param_error` / `not_found` / `permission_denied` 直接放弃。
    - `network_error` / `rate_limited` 与解析失败带 1s/2s/4s 退避重试。
  - 重试提示语携带具体错误类型，而非笼统「调整方式」。
  - `run_with_requests` 使用 `ThreadPoolExecutor` 并行执行多个请求。

- 各工具实现
  - `tools/web_tools.py`：`web_search`、`web_fetch` 标注 `network_error` / `not_found` / `param_error`，设置 `timeout_seconds=45`。
  - `tools/file_tools.py`：`read_file`、`file_tree` 标注权限/不存在/参数错误。
  - `tools/search_tools.py`：`glob`、`grep` 标注参数错误与未找到。
  - `tools/music_tool.py` / `tools/notify_tool.py` / `tools/memory_tools.py`：按场景标注错误类型。
  - `memory_tools` 的 `recall` / `remember` 标记 `is_internal=True`。

- `core/monitor.py`
  - 新增 `ToolMetrics` / `ToolMetricsCollector`。
  - 新增 `record_tool_metric()`、`get_tool_metrics()`。
  - dispatcher 每次工具调用自动上报成功率、延迟。

- `core/message_handler.py`
  - `_make_external_registry()` 额外过滤 `is_internal=True` 的工具，防止内部工具意外暴露。

- `web/server.py`
  - 新增 `GET /api/tools/metrics` 端点，供 Web 面板查询 per-tool 成功率与平均延迟。

- 测试
  - `tests/test_dispatcher.py`：新增参数校验、权限拒绝、超时、并行执行、工具指标测试。
  - `tests/test_tool_agent.py`：新增非重试错误早停、可重试错误重试测试。
  - `tests/mocks.py`：mock tool 补充 `timeout_seconds`、`parameters_schema`、`required_permissions`。

## 验收结果

- 全量测试：`716 passed, 2 skipped`。
- 新增 12 个测试用例覆盖方案中的 6 项验收点。
