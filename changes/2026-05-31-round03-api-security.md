## 修改内容摘要

新增 API 密钥与认证安全审查报告，覆盖以下 8 个审查维度：

1. **API 密钥存储方式** — 发现 `config.json` 明文存储真实 DeepSeek API 密钥（sk-618d...），且已提交至 Git 历史
2. **密钥在日志中的泄漏风险** — 日志系统缺乏全局脱敏过滤器，`requests` 调试日志和异常堆栈可能暴露密钥
3. **密钥在内存中的生命周期** — `DeepSeekProvider` 长期以明文 `str` 持有密钥，Python 字符串不可变性导致内存残留
4. **请求头中 Authorization 的传输安全** — 未显式强制 TLS 1.2+，依赖系统证书存储存在中间人风险
5. **配置文件的权限和访问控制** — `config.json` 权限为 `0o666`，其他用户可读
6. **.gitignore 是否有效保护密钥** — 已忽略 `config.json` 但缺少备份文件、临时文件、IDE 配置的保护
7. **多用户场景下的密钥隔离** — Web 模式下所有会话共享同一 `Config` 和 `api_key`，无用户级隔离
8. **密钥轮换机制** — 无多密钥配置、热重载、失效检测、轮换审计等机制
