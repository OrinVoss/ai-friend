# 两阶段 Agent 架构：职能分离解决工具调用问题

**时间**：2026-05-30

## 问题

DeepSeek 模型系统性编造工具调用内容，三层补丁（假调用检测+重试、tool_result 诚实指令、误判修复）未能根治。根因是角色扮演人格提示词与工具调用指令混在同一 Agent 中，模型在人格驱动下倾向叙事描述而非输出 `<tool_call>` XML。

## 方案

职能分离：将单 Agent 拆分为两个阶段。

```
用户输入
    │
    ▼
Phase 1: Tool Agent（纯工具层）
    - 无角色、无情绪、无记忆
    - temperature=0.3
    - 提示词仅含 7 个外部工具定义 + 调用规则
    - web_fetch, web_search, read_file, glob, grep, music_play, notify
    - 输出完整工具调用记录传给 Phase 2
    │
    ▼
Phase 2: Roleplay Agent（角色层）
    - 完整人格、情绪、记忆
    - temperature=0.8
    - 提示词含 Phase 1 工具调用记录
    - 内部工具保留：recall, remember
    - 外部工具指令完全移除
    │
    ▼
后处理：情绪计算 → 记忆合并 → 反思（不变）
```

## 修改文件

### 新建

- `core/tool_agent.py`（120 行）— Phase 1 纯工具 Agent
  - `ToolAgent` 类：仅注册外部工具，独立 ReAct 循环
  - `ToolCallRecord` / `ToolAgentResult` 数据类
  - `format_for_phase2()` 格式化工具记录给 Phase 2

### 修改

- `prompts/system.py` — 新增 `build_tool_agent_prompt()`；`build_system_prompt()` 新增 `tool_records` 参数，外部工具从角色提示词中移除，仅保留 recall/remember
- `core/message_handler.py` — `handle_message()` 和 `handle_explore()` 添加 Phase 1 调用编排
- `core/cli_controller.py` — `_on_perceive()` 运行 Phase 1，`_on_think()` 注入工具记录
- `tools/traits.py` — `format_for_prompt()` 新增 `names` 过滤参数
- `tests/mocks.py` — 新增 `mock_tool_registry()`
- `tests/test_message_handler.py` — 适配新架构

## 设计原则

- **外部工具 Phase 1，内部工具 Phase 2** — 编造风险集中在外部内容获取，内部 recall/remember 操作本地数据库无编造风险
- **Phase 1 全部记录传给 Phase 2** — 调用了什么、成功/失败、返回内容，完整透传
- **Phase 2 不再输出外部工具 XML** — 提示词中完全没有 web_/read_file/glob/grep/music/notify 工具
