# 两阶段 Agent 架构：职能分离解决工具调用问题

**时间**：2026-05-30

## 问题

DeepSeek 模型系统性编造工具调用内容，三层补丁（假调用检测+重试、tool_result 诚实指令、误判修复）未能根治。根因是角色扮演人格提示词与工具调用指令混在同一 Agent 中，模型在人格驱动下倾向叙事描述而非输出 `<tool_call>` XML。

## 方案

职能分离：将单 Agent 拆分为两个阶段。

```
用户输入
    │
    ▼
Phase 1: Tool Agent（纯工具层）
    - 无角色、无情绪、无记忆
    - temperature=0.3
    - 提示词仅含 7 个外部工具定义 + 调用规则
    - web_fetch, web_search, read_file, glob, grep, music_play, notify
    - 输出完整工具调用记录传给 Phase 2
    │
    ▼
Phase 2: Roleplay Agent（角色层）
    - 完整人格、情绪、记忆
    - temperature=0.8
    - 提示词含 Phase 1 工具调用记录
    - 内部工具保留：recall, remember
    - 外部工具指令完全移除
    │
    ▼
后处理：情绪计算 → 记忆合并 → 反思（不变）
```

## 设计原则

- **外部工具 Phase 1，内部工具 Phase 2** — 编造风险集中在外部内容获取，内部 recall/remember 操作本地数据库无编造风险
- **Phase 1 全部记录传给 Phase 2** — 调用了什么、成功/失败、返回内容，完整透传
- **Phase 2 不再输出外部工具 XML** — 提示词中完全没有 web_/read_file/glob/grep/music/notify 工具

## 日志系统

新增 `[tool_agent]` 标签，覆盖 Phase 1 全流程：
- `[tool_agent] start` — Phase 1 开始（输入长度）
- `[tool_agent] iter=N/M` — 迭代进度
- `[tool_agent] done` — 结束（调用数/成功数/耗时）
- `[msg] phase1` — Phase 1→Phase 2 过渡（工具汇总）

provider `[api]` 和 dispatcher `[tool]` 标签自动覆盖 API 调用和工具执行。

## Bug 修复

### ToolAgent 未运行（懒初始化）
`ToolAgent` 在 `MessageHandler.__init__()` 创建时 `agent._tool_registry` 为空——工具在 Agent 构造之后才注册。`ToolAgent.run()` 检测到空注册表直接返回，Phase 1 静默跳过。

修复：`_ensure_tool_agent()` 懒初始化，首次 `handle_message()` 调用时创建。

### Phase 2 重复调用外部工具
Phase 1 完成后，Phase 2 的 `_react_loop` 仍使用全量 `tool_registry`，模型可能再次输出 `<tool_call>web_fetch` 导致重复执行。

修复：
- `_react_loop` 新增可选 `tool_registry` 参数
- Phase 1 运行后，Phase 2 使用过滤注册表（仅 recall + remember）
- `_make_internal_registry()` 创建仅含内部工具的注册表
- CLI 路径 `_on_act` 同样过滤
